## Fuehrungen Workflow

- Start each new Fuehrung pass by inspecting:
  - `plugins/iss-fuehrungen`
  - `plugins/iss-relations`
  - `themes/industriesalon/templates/single-tour.html`
  - `themes/industriesalon/templates/single-tour-on-demand.html`
- Keep one shared single-tour template for all Fuehrungen.
- Keep booking logic in the plugin/domain layer. The theme should only render booking UI and related layout.
- Keep route data in `iss_related_places`. Do not create theme-local route storage or a parallel per-page system.
- Use `register_place` as the shared route-station entity.
- Keep route-specific overrides on the Fuehrung relation row:
  - `route_title`
  - `route_teaser`
  - `station_object_id`
  - `station_story_id`
- Treat Atlas and route as two views of the same `register_place`:
  - Atlas shows Atlas only
  - tour pages show route only
  - do not mix route order or booking logic into Atlas views
- Before adding route relations:
  - read the current tour script
  - match stations to existing `register_place` records where possible
  - search `archivobjekt`, posts, publications, and places for relation candidates
  - add only strong relations; do not force weak matches
- For station media:
  - prefer `archive_images` for `Damals`
  - prefer `current_images` for `Heute`
  - keep route styling in isolated feature CSS, not in global overrides
- When station coordinates are unclear from the script, stop and confirm the anchor before saving coordinates.
- Use the ordered route helper `iss_relations_get_ordered_route_items()` for frontend rendering instead of duplicating route queries in templates.
